# 照片低成本測試（2026-10-21）

照片來源：Pexels（免費授權），MediaPipe Pose Landmarker heavy，和網頁 demo 同一套算法。
跑法：`../Single-Photo-VRM/template/.venv/bin/python run.py photos`、`run2.py side side`、`run2.py squat squat`。

## 1. 坐姿，正面鏡頭（12 張，`sheet.jpg`）
- 只有 4 張接近正面；側面、背面時比值爆掉，程式照樣打分數。背影也被當成正面的人。
- 同一人（3987030 vs 3987031）明顯駝的那張，「耳高／肩寬」只低 9%。原門檻 25% 不會提醒。
- 已修：鼻子比耳朵靠近鏡頭（正面 −0.28～−0.39、側面約 0、背面 +0.33）才判斷；門檻改 15%。

## 2. 坐姿，側面鏡頭（14 張有偵測到人，`sheet-side.jpg`）
- 頭頸角（耳–肩連線對水平）：最駝的兩張最低（18°、37°），坐直的 56°～85°。排序和肉眼一致。
- 側面直接量頭頸角，比正面間接推測直接；但身體整個往前靠（7256315，66°）抓不到。

## 3. 深蹲（18 張，`sheet-squat.jpg`）
- 側面拍（7 張）：demo 用的 3D 膝角和照片上的 2D 角度平均差約 6°，最大約 19°。
- 正面拍：2D 角度完全不能用（明顯深蹲讀成 95°～142°），只能靠 3D 估；3D 數值合理但無法從照片驗證，左右腳差到 15°～17°。
- 側面時被擋住的那條腿 2D 會亂掉（4908608 讀成 175°）；demo 取兩腳平均，一條壞腿會拖累。

## 限制
- 不是同一人、同一場景的受控比較；沒有真值，側面 2D 角度只是近似真值。
- 門檻依少量照片調整。

## 4. 資料集：MultiPosture（Zenodo 14230872，CC BY 4.0，13 人、4,794 幀）
`multiposture/eval.py`。每人用自己「坐直」幀的中位數當校準，套用 Desk Buddy 正面規則：
- 左傾／右傾：98% 抓到（肩歪指標很穩）
- 前傾：60% 抓到；坐直誤報 22%；後仰 28%
- 門檻取捨：前傾門檻 8% → 抓 68%／誤報 31%；25% → 抓 50%／誤報 15%
- 個體差異大：受試者 12 的前傾 0/60，受試者 10 是 38/38
- 「有沒有正對鏡頭」的門檻是用影像座標調的；這份資料是髖部中心公尺座標，所有人都落在 −0.12 附近，必須換尺度

## 5. 連續動作影片（Pexels，4 支伸展、3 支深蹲，`out-video/`、`*-timelines.jpg`）
- 深蹲：正面站直只讀到 148°～155°，原本「>160° 才算站起來」→ 兩支影片都數成 0 下。改 140° 後：4 下、6 下、9 下，和曲線上的下蹲次數一致
- 伸展：側頭和轉頭都抓得到，但人自然停留約 2.8～3.3 秒，3 秒門檻會漏 → 改 2 秒
- 側頭時耳朵中點也變低，會被誤判成聳肩（一支影片假聳肩 4.8 秒）→ 頭要擺正才算聳肩，之後降到 0.3 秒
- 沒找到真正聳肩的影片，聳肩「抓得到」還沒驗證
